**结论**：在本卡「撤销后修改已有组并保留训练日期，再完成」路径上，不会产生重复事件，也不会因再次完成给教练新增重复推送/信号。completed、partial 两种归档状态均有 API + 作业回归，完整 events/signals/outbox 前后相等。无需副作用生产修复。

既有账本是事实记录，不随撤销重写/撤回；例如 partial 仅改次数仍保持 partial，已有 PR 事实也不因改次数被重算撤回，这些规则本卡保持。新增组、显式移动 logged_date、首次达成新的 PR 属于不同输入，不据本回归断言它们永远无新事件。已发推送也不会撤回。本地验证到持久化队列边界，没有发送真实 APNs，不能证明推送网络重试的 exactly-once 交付。
