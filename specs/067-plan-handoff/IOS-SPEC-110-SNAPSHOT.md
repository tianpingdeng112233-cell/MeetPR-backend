## 问题与已核实事实

- 学员端两端都从已发布计划里取 `published_at` 最大的一份：iOS `BackendStudentPlanRepository.planPrecedes`，Android `selectCurrentPlan`（8 处调用，含成长页汇总、聊天分享、教练端学员列表与详情）。不看开始日，也不看上一份是否练完。
- 后端发布只更新目标计划自身，同一学员可同时有多份 published 计划，日期可以重叠，没有任何校验。
- 学员端是推进制：游标日是按顺序最早一个未结算的训练日，推荐日期只是参考。
- **现网垫片**：[MeetPR-backend#412](https://github.com/tianpingdeng112233-cell/MeetPR-backend/pull/412) 已上国内 staging（`ef17157`）。学员请求 `GET /students/:studentId/plans` 时，若有计划覆盖学员当地今天，则不返回 `start_date` 在未来的计划。反馈学员已确认本周计划恢复。它按日期切换，与下述规则不一致：到新计划开始日旧包仍会切走。反馈中的新计划 2026-11-23 开始。

## 已确认规则（David 2026-11-16）

1. **练完再接**。学员正在练的计划只要还有未结算训练日，新计划的发布、重新发布、改日期、刷新、重启都不替换它。全部训练日结算后自动接下一份。不以日历日期为开关。
2. **正在练的计划由服务端推导，不存指针、学员不做任何选择**。在同一次绑定的已发布计划中：
   1. 取最近一次有训练记录（组记录或训练日结算）的计划作为锚；它还有未结算训练日，就是它。
   2. 锚已全部结算，取 `start_date` 在它之后、最近的一份有未结算训练日的计划。
   3. 完全没有训练记录，取 `start_date` 最早且有未结算训练日的计划。
   4. 都没有，取最近发布的一份，显示周期完成态。
   休息日不计入「未结算」；没有训练日的空计划不参与接续。
3. **存量无感**。规则 2 对存量学员直接成立，升级后不出现任何选择界面，不批量改线上计划状态。更早留有弃练尾巴的学员不会被拉回旧计划（锚在他最近练的那份）。
4. **学员可以往后翻看下一份计划，只读**。训练页周条翻过当前计划最后一周即进入下一份已发布计划，可看不可记录；各计划各自从 W1 起，交界处有「新周期」分隔。练到那一份时才可记录。
5. **教练端禁止日期重叠**。同一学员同一次绑定内的 published 计划，日期范围不得重叠，含同一天落两份计划的训练。后端在发布、改开始日、加周数三处校验，返回冲突的计划与日期；网页给出明确提示，新建计划的开始日默认填上一份结束次日。范围取 `start_date` 至「`end_date` 与后移后实际最后训练日」的较晚者。
6. **不提供「结束上一份」或切换入口**。David：「没影响，只要不重叠就好」。教练想丢掉旧周期尾巴，回旧计划删掉未练的训练日。
7. **其余读「正在练的那份」**。成长页汇总、聊天里分享某一组、教练端学员列表与学员详情、网页的学员游标与周吨位，统一读规则 2 的结果，不做跨计划浏览。

## 具体行为

### 学员端（iOS / Android）

- 最后一节结算成功后，奖励、回顾、撤销界面仍指向刚完成的那天；关闭后下一次进入训练页落在下一份的首个未结算日。不在填写、拍摄、上传中途替换页面。
- 没有下一份则显示现有周期完成态；之后教练发布下一份，自动接上。
- 撤销旧周期最后一天：新周期尚无训练记录时，按规则 2 自然回到旧周期；新周期已有记录则留在新周期。不清任何记录。
- 只读翻看：下一份计划的训练日显示处方，不显示勾选、拍摄、完成按钮，顶部或分隔处写明「练完当前周期后开始」。布局以定稿屏幕稿为准。
- 离线：有本地缓存时继续当前缓存的训练，联网后以服务端结果为准；结算仍在待同步时不提前切到下一份。

### 教练网页（plan-web）

- 计划下拉与当前查看的计划，在发布状态之外标出「学员正在练」/「待接续」；请求失败显示未知可重试，不回退猜最新。
- 学员进度、游标、周吨位读服务端结果。现状 `PlanWorkspace.fetchRosterWeekTonnage` 按 `updated_at` 取第一份、`activePublishedPlanId` 取列表第一份，都要改。
- 发布成功提示如实表达：学员当前计划未练完时为「已发布，学员练完当前计划后自动接续」。
- 发布、改开始日、加周数遇到日期重叠时，展示后端返回的冲突计划与日期。
- 教练后移上一份计划会越过下一份开始日时，下一份的推荐日期一并顺延同样天数；操作前确认框写明「下一份计划也会顺延 N 天」。
- 与 `specs/030-previous-cycle`（编辑器带出上一周期，[plan-web#175](https://github.com/tianpingdeng112233-cell/meetpr-plan-web/pull/175)）同改 `PlanWorkspace` 一带，本卡在 #175 合并后从最新 `main` 开工。

### 后端

- 新增只读契约：返回该学员「正在练的计划 id」及按接续顺序排列的已发布计划摘要（含每份的已结算 / 总训练日数）。教练可读自己学员的，学员只能读自己的。路由与字段由后端卡固定，再以同一组 fixture 驱动三端。
- **旧包兼容**（未升级的 iOS / Android 仍用原列表接口并自取 `published_at` 最大者）：原列表接口对学员角色改为不返回「`published_at` 晚于正在练的那份」的其他计划，使旧包也落在正在练的那份上。它取代 #412 的按日期过滤。新客户端带显式参数取完整列表。后端卡须先核实两端已发布版本对该列表的全部用途，确认隐藏不会破坏别的页面，否则回报而不是硬改。
- 日期重叠校验见规则 5。存量已重叠的计划不改数据：上线前用只读查询出清单给 David 过目；学员端对存量重叠按接续顺序依次练，不丢任何一天。
- 无迁移为目标。若确需索引或字段，additive，迁移号开工现场核实。

## 测试 seam

- **backend**：HTTP 层打新契约与原列表接口（学员 / 教练 token），复用 `tests/plans` 与 `tests/helpers` 夹具；「正在练」推导抽纯函数单测覆盖规则 2 四支。重叠校验打发布、PATCH 开始日、加周数三条路由。
- **iOS**：`StudentPlanRepository` 公开边界 + HTTP fixture，验证冷启、刷新、结算后接续、撤销回退、缓存；`TodayWorkoutViewModel` 验证只读翻看不产生写入。
- **Android**：公开仓储与训练 screen，消费同一 fixture；`selectCurrentPlan` 的 8 处调用全部改走服务端结果，不保留「最后发布」排序。
- **web**：`PlanWorkspace` 组件 + API fixture。
- 每个行为先红后绿。完整验收必须经过真实 API，demo 只证明布局。
