## 1. 背景与拍板

现状 plan-web 是全景 Excel 网格:纵向 W01→W05 排周、每周横摊 7 天,一屏看全但
每格都小,写单周计划时信息密度过载。David 2026-08-10 拍板改为 PowerSheets 式
「周带聚焦」布局,五条裁决:

1. **骨架对齐拍 A:渲染层对齐,数据模型不动**——每周每天仍是独立
   plan_days/plan_exercises,周间可换动作;冻结骨架列由渲染层按并集对齐。
2. **骨架列加「目标部位」**:动作左侧显示部位/主项徽章。
3. **只做处方侧(TARGET)**:实际完成(ACTUAL)列组本波不做,deferred(数据接口
   追踪波已有,将来另 spec)。
4. **D1 周几 = 沿用位置式正典 + 教练自选锚**:`day_of_week` 位置式(D1=计划第 1 天,
   2026-07-10 拍板)不动;新增**计划级**锚「D1 落在周几」,教练可选,D2…Dn 顺推
   显示周几标签。不做 per-week 锚(PowerSheets 实测也是骨架级而非每周各选)。
5. **横移机制照搬**:连续周带 + 横向滚动平移 + week tab scroll-spy。

## 2. 布局机制(照搬 PowerSheets 实测,MeetPR 化)

### 2.1 周带(week band)

- 编辑器主体是**一条连续的横向周带**:Week 列组从左到右拼接(W01 | W02 | …),
  横向滚轮/触控板平移;视口宽度 ≈ 一周列组宽度(一屏一周)。
- 顶部 **week tab 条**(W01…Wnn + 「+ 加一周」):滚动侦听(scroll-spy)——滚到哪周
  该 tab 点亮;点 tab 平滑滚动到该周。现有「跳到周」下拉退役,由 tab 条取代。
- 滚动到两周交界时自然并排显示相邻两周(跨周对照写递进的核心场景,无需额外 UI)。

### 2.2 冻结骨架列(渲染层对齐)

- 左侧冻结列:`# | 目标部位 | 动作名`,横滚时钉住不动。
- **对齐算法(渲染层,模型不动)**:以「训练日序数 × 动作」做行对齐——
  - 天级:各周的 D1 对齐同一天块,D2 对齐 D2…(位置式序数天然对齐);
  - 动作级:同一天块内,按 exercise_id 求各周的**并集**,行序取「首个出现该动作的周」
    的行序,同 id 对齐同一行;某周该天没有这个动作 → 该周该行显示空格(—,可点击
    快速添加);某周独有的动作照常占一行,其他周该行空。
  - 分节(主项及变式 / 辅助项)保持现状,在天块内分节对齐。
- 目标部位徽章:主项/主项变式显示 lift 徽章(蹲/卧/拉,沿用系列色),辅助项显示
  catalog 主肌群中文名。数据全部来自现有 `GET /exercises` catalog,无后端改动。

### 2.3 周内结构

- 周列组内,训练日 D1…Dn **纵向堆叠**(天块 = 日头部 + 动作行),替代现状的
  7 天横摊;日头部含:D 序数 + 周几标签(见 §3)+ 日期(若可推导)+ 现有日级操作
  (设为休息 / 清空本日 / 复制上周计划到本周)。
- 列结构沿用 spec 034 v2.1 终态:`组数 | 次数 | 强度 | 重量 | 备注`。
- 现有交互全部保留:批量选择、键盘导航、多选、拖拽搬日(改为周带内跨天块拖拽)、
  autosave、发布门禁。**全景 Excel 网格退役**,缩放控件随之退役(周带下无意义)。

## 3. D1 周几锚(backend W0)

### 3.1 迁移 `db/migrations/00XX-plan-anchor-weekday.sql`

(**编号实装现场取号**;写作本 spec 时 staging 账本 head = 0059。)

```sql
ALTER TABLE plans ADD COLUMN anchor_weekday SMALLINT;

ALTER TABLE plans ADD CONSTRAINT plans_anchor_weekday_check CHECK (
  anchor_weekday IS NULL OR anchor_weekday BETWEEN 1 AND 7
);
```

- 语义:**展示锚**——`1=周一 … 7=周日`,表示「本计划的 D1 落在周几」;
  NULL = 未设置(现状,不显示周几标签)。
- `day_of_week` 位置式正典**不动**:D_n 的周几 = `((anchor_weekday - 1 + n - 1) mod 7) + 1`,
  纯派生,不落库、不参与顺延/推进制/结算任何口径(它们继续只认位置序数)。
- 超过 7 天的周期(如 10 天一循环)照常取模,标签如实轮转,不做特殊处理。

### 3.2 API

- `PATCH /plans/:id`(或现有计划元数据更新端点)接受 `anchor_weekday`(1–7 或 null),
  权限同计划编辑;计划树响应带出该字段。纯 additive,老客户端零感知。

## 4. plan-web(W1 主体)

- 周带虚拟化:只挂载视口周 ±1 周的列组 DOM(mesocycle 可达 12+ 周,全量挂载会卡);
  骨架列与周列组滚动同步。
- week tab scroll-spy 用 IntersectionObserver;点 tab `scrollTo({behavior:'smooth'})`。
- 日头部周几标签:计划未设锚时显示「设周几」入口(轻量下拉,选完 PATCH 落库);
  已设锚时 D1 头部可再点改。
- xlsx 导入、DSL 解析、剪贴板、撰写上下文栏、强度/重量列(spec 034 v2.1)行为不变——
  本波**只动布局层**,单元格编辑组件原样复用。
- 走查基线:改版前先截全景网格各态存档(对照用);上线前跑 /walkthrough 教练角色
  过一遍「写一份 4 周计划 + 跨周对照改递进」主流程。

## 5. 验收标准

1. backend:迁移应用后存量行 `anchor_weekday IS NULL`;PATCH 写入 1–7/null 回读正确,
   越界 422;计划树响应带出;既有端点快照回归。
2. plan-web:
   - 周带横滚流畅(12 周计划无明显掉帧,虚拟化生效);tab scroll-spy 与点击互通;
   - 骨架对齐:构造「W2 比 W1 多一动作、少一动作、完全不同动作」三例,行对齐与
     空格显示正确,空格点击可快速添加;
   - D1 设锚后各天周几标签顺推正确(含 >7 天计划取模);
   - 现有编辑能力(强度/重量/批量/键盘/拖拽搬日/autosave/门禁)在新布局下全量回归;
   - 全景网格与缩放控件退役,无死入口。
3. lint/build/test 全绿;两仓各自 PR;plan-web 侧 review-loop 收敛;模拟器/浏览器
   亲验截图交付。
