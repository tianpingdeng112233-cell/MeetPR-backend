# Spec 049 · 中文官网、教练目录与教练主页

- Status: Draft
- 来源：David 2026-10-12 /grill 四轮 + 「确认」。
- 级别／节奏：T3 / P1（新的用户可见形态 + 迁移 + 第一批免登录公开接口）。每个 PR 的合并与部署都等 David「放行」；**公网正式上线另有一道 David 放行**，放行前只在测试环境验收。
- 本 spec 是三仓共用的正典：后端（本仓）、教练网页端 `meetpr-plan-web`、官网 `meetpr-site`。另两仓开卡时只放指向本文件的指针，不复制正文。
- iOS 与安卓 app 本期一行不改。
- 先读：仓根 `CONTEXT.md`（教练主页、教练目录、核实数据、教练自述、招生申请、订阅到期日）。

## 问题（为什么做）

教练需要一张能拿出去招生的页面，学员需要一个能看到教练真实带训情况的地方。MeetPR 手里有别处没有的东西：教练在工具里带训留下的真实记录。本期把这些记录变成每位教练的公开主页，并用官网上的教练目录把主页汇到一起。

## 现状（2026-10-12 现场核实，`origin/staging@ca88b88`）

- `coach_profiles` 只有 `display_name`。没有简介、短名、公开状态，也没有任何订阅字段。
- 后端除 `/health` 与 `/auth/*` 外没有免登录接口。
- 可如实计算的带训数据都已在库：绑定关系（`bind_requests`）、训练日完成（`plan_day_completions`）、组记录与 e1RM（`set_logs`，口径见 `src/handlers/exercise-stats.ts` 的 `buildE1RMSeries`）、破纪录事件（`student_events` 的 `pr_e1rm`）、视频与教练首次反馈（`attachments`、`feedback`、`video_markers`）。库里没有比赛成绩。
- 网页端已有管理员后台页（`meetpr-plan-web` 的 `src/features/admin`，后端 `/admin/*` 需 `admin` 角色）。
- 官网 `meetpr.cn` 现在是一张静态页，由独立的一台服务器直出，与后端不在同一台机器上；它的源码不在任何仓里。
- 用户头像（spec 047）尚未实装，且它写的迁移号 0072 已被 048 占用，实装时须重排。

## 已拍板口径

| 题 | 结论 |
| --- | --- |
| 形态 | `meetpr.cn` 是中文官网，导航只有「首页」「教练目录」；教练主页是从目录点进去的详情页，同时可凭自己的链接直达 |
| 访问方式 | 手机优先，免登录、免装 app；首版只做中文 |
| 官网首版范围 | 首页、教练目录、教练主页、页脚（隐私政策、备案号、教练登录入口）。不做下载页和独立定价页 |
| 首页 | 以 `meetpr-site` 的 `landing-v2` 分支结构为底改写成中文；首屏对教练说话并加「教练主页」卖点，学员找教练放第二屏；保留定价区块，价格位显示「即将公布」 |
| 教练入驻入口 | 首页放管理员的微信二维码，线下沟通后由管理员开号并设置订阅到期日 |
| 入驻门槛 | 教练账号有「订阅到期日」，管理员手动设置；到期后主页下线、从目录移除、不再接收招生申请，续期即恢复。不做在线支付 |
| 主页内容 | 头像置顶；教练自述（一句话简介、简介、擅长方向）可填；核实数据只读、系统生成；最下面是招生申请表单 |
| 核实数据 | 三类都放：带训规模、学员进步、响应速度 |
| 学员隐私 | 一律匿名，不需要学员逐人同意；隐私政策补一条说明 |
| 学员进步 | 不设最低带训周数；全部学员照实列出，含零和负数；每条带周数 |
| 数据起点 | 只认学员在该教练计划下自己记录的首个有效成绩；导入的历史估算不算 |
| 公开与审核 | 系统生成草稿，教练预览后手动申请公开；首次公开须管理员审核，审核页同屏显示原始数字；之后的自述改动先发后审 |
| 目录 | 极简列表（头像、名字、擅长方向、在带人数、一句话简介），无筛选、无比较；按入驻时间排序；公开教练不足 5 位时官网导航与首页不出现目录入口，目录页地址本身照常可访问 |
| 链接 | `meetpr.cn/c/<教练自选短名>`；可一键下载带二维码的海报图 |
| 招生申请 | 访客在主页留表单；教练在网页端看列表并收邮件提醒；线下沟通后用现有邀请码绑定。平台不介入之后的带训与收款 |
| 教练操作在哪端 | 全在网页端 |

## §1 词与状态

**对外可见**是唯一的总闸，三个条件同时成立才算：

1. 主页状态为「已公开」；
2. 订阅到期日晚于当前时刻；
3. 没有被管理员下线。

任一不成立：主页地址回「未开放」页（404），目录里不出现，招生申请接口拒收。

主页状态：

```
草稿 ──教练申请公开──▶ 待审核 ──管理员通过──▶ 已公开 ◀──教练恢复── 已隐藏
  ▲                      │                      │  └──教练隐藏──▶ 已隐藏
  └────管理员退回(附理由)──┘                      └──管理员下线──▶ 已下线 ──管理员恢复──▶ 已公开
```

- 首次「管理员通过」的时刻记为**入驻时间**，一经写入不再改变，目录按它升序排。
- 通过首审之后，教练隐藏再恢复不需要重新审核。
- 已公开状态下教练改自述：立即对外生效，同时打上「改动待看」标记；管理员看过后清除标记，或直接下线。
- 被管理员下线的主页教练不能自行恢复。

短名：3–20 位，小写字母、数字、连字符，首尾不能是连字符；全站唯一；保留词（`admin`、`api`、`c`、`coaches`、`privacy`、`www`、`app`、`meetpr`、`login`）不可用。首次通过审核后教练不能再改，只有管理员能改（避免已发出的二维码失效）。

## §2 核实数据口径

全部由后端从现有带训记录实时计算，任何角色都不能写入。统计范围＝该教练名下的计划所产生的记录，与教练端成长曲线同一取数范围。

### 带训规模

- **带训起始**：该教练第一条被接受的绑定的接受日期，展示为「带训 N 个月」（不足 1 个月展示周数）。
- **在带学员数**：当前与该教练存在已接受绑定的学员数（一名学员有多条已接受绑定时，按 `src/db/bonds.ts` 的既有规则只归属一位教练）。
- **累计学员数**：曾与该教练有过已接受绑定的不同学员数。
- **完成训练课数**：该教练名下计划里已完成的训练日总数。

### 学员进步

- 一名学员一行，按带训周数从长到短排，展示名为「学员 A」「学员 B」……。不出现姓名、头像、账号、日期与任何 id。
- 逐项（深蹲、卧推、硬拉）计算，取数与过滤完全沿用 `buildE1RMSeries`：只算比赛动作族、排除 `assumed` 与低置信度记录、每天取当日最佳。
  - **起点**＝该学员该项最早一个有效日点的 e1RM。
  - **现值**＝截至该学员最后一条有效记录当天、向前 28 天窗口内的最佳日点（即现有的滚动窗口口径）。
  - **变化**＝现值 − 起点，保留到 0.5 kg，可为零或负数。
  - **周数**＝该项最早有效日点到最后有效日点之间的整周数，不足 1 周记 1 周。
- 某项没有任何有效日点：该项不展示。三项都没有：该学员不出现在本块，但仍计入带训规模。
- **破纪录次数**：归属该教练的 `pr_e1rm` 事件总数，全体学员合计一个数。
- 没有任何学员有可展示的行：整块不出现。

### 响应速度

- 统计对象：近 90 天内，该教练的学员上传完成的组视频中，教练已给出反馈的那些。
- 一条视频的响应时长＝视频记录创建时刻到教练对它的首次反馈（`feedback` 或 `video_markers`，取较早者）之间的时长。
- 展示中位数（不足 1 小时按分钟，否则按小时取整）和样本数（「基于 N 条视频」）。
- 样本数为 0：整块不出现。

### 新鲜度

每次返回都带一个「数据截至」时刻。可以做短时缓存（不超过 10 分钟），不做离线预计算。

## §3 数据模型（一支纯加法迁移，迁移号实装时现场核实）

- 新表 `coach_pages`，一位教练至多一行：短名（可空、唯一）、一句话简介、简介、擅长方向（标签数组）、状态、入驻时间、退回理由、改动待看标记、时间戳。
- `coach_profiles` 新增 `subscription_expires_at TIMESTAMPTZ NULL`。
- 新表 `coach_enquiries`：所属教练、称呼、联系方式、三项现成绩（可空）、目标、状态（新申请／已联系／已关闭）、提交时刻。
- 不改任何现有列与现有行；`src/db/types.ts` 手工补类型。
- 删号：教练账号删除时，主页与其招生申请随之删除。

长度与数量上限：一句话简介 ≤ 30 字；简介 ≤ 500 字；擅长方向 ≤ 5 个、每个 ≤ 10 字；称呼 ≤ 30 字；联系方式 ≤ 100 字；目标 ≤ 500 字；三项成绩 0–600 kg。

## §4 后端接口

所有新增接口都是加法，现有接口的路径、字段与取值一个不改。

### 免登录（`/public/*`）

单独限流（按来源地址），不读取也不下发任何登录态。

- `GET /public/coaches` → `{ total, coaches: [{ slug, display_name, avatar_url, headline, specialties, active_student_count }] }`，只含对外可见的教练，按入驻时间升序。
- `GET /public/coaches/:slug` → 教练自述 + §2 三块核实数据（没有数据的块为 `null`）+ `data_as_of` + `accepting_enquiries`。不存在或不对外可见一律 404 `COACH_PAGE_NOT_FOUND`，不区分原因。
- `POST /public/coaches/:slug/enquiries` → 请求体：称呼、联系方式、三项现成绩（可选）、目标（可选）、`consent: true`。成功 201，不回显任何已存内容。教练不对外可见 → 404 同上。校验失败走现有校验信封。同一来源地址对同一教练 24 小时内至多 3 条，超出 429。请求体带一个诱饵字段，被填了就回 201 但不入库。

`avatar_url`：教练有头像时下发一个有时效的读地址，没有时为 `null`（官网用名字首字占位）。头像的上传与存储由 spec 047 负责，本 spec 不新增头像通道；047 落地前该字段恒为 `null`。

### 教练（`/coach/*`，需教练角色）

- `GET /coach/page` → 自己的主页（没有则当场建一份草稿：短名为空、自述为空）、状态、退回理由、订阅到期日与是否已到期、对外地址、以及与公开主页同口径的核实数据预览。
- `PUT /coach/page` → 改自述与短名。短名冲突 409 `COACH_PAGE_SLUG_TAKEN`；格式或保留词不合规 400；首审通过后再改短名 409 `COACH_PAGE_SLUG_LOCKED`。
- `POST /coach/page/submit` → 草稿进待审核。前置：短名已设、一句话简介非空、订阅未到期；不满足 409 并指明缺哪一项。
- `POST /coach/page/hide`、`POST /coach/page/show` → 已公开与已隐藏之间切换。`show` 只在通过过首审且未被下线时可用。
- `GET /coach/enquiries` → 自己的招生申请，新到旧。
- `PATCH /coach/enquiries/:id` → 改状态。只能改自己的，别人的回 404。

### 管理员（`/admin/*`，沿用现有的管理员二次校验）

- `GET /admin/coach-pages` → 全部教练的主页状态、订阅到期日、改动待看标记，以及每位教练的核实数据原始数字（含学员进步每行的起点与现值）。
- `POST /admin/coach-pages/:coachId/approve`、`/reject`（必填理由）、`/suspend`、`/restore`、`/mark-reviewed`。
- `PUT /admin/coach-pages/:coachId/slug` → 管理员改短名。
- `PUT /admin/coaches/:coachId/subscription` → `{ expires_at: <时刻> | null }`。

### 邮件提醒

新的招生申请入库后，给该教练账号的邮箱发一封提醒（只写「你有一条新的招生申请」和网页端入口，不写访客填的任何内容）。教练没有邮箱、或本部署没配发信：跳过并记日志，不影响 201。

## §5 教练网页端（`meetpr-plan-web`）

- 教练导航新增「我的主页」：编辑自述与短名、看状态与退回理由、看订阅到期日、预览（与公开主页同样的版式和数据）、申请公开、隐藏与恢复、复制链接、下载二维码海报。
- 教练导航新增「招生申请」：列表、未处理数量角标、改状态；每条旁边有「去生成邀请码」的指引，走现有邀请码功能。
- 管理员后台新增「教练主页」：待审核队列、改动待看队列、通过／退回／下线／恢复、设置订阅到期日；审核时同屏显示该教练核实数据的原始数字。
- 订阅未设置或已到期时，「我的主页」仍可编辑与预览，但不能申请公开，并显示「订阅未生效，联系管理员」。

## §6 官网（`meetpr-site`，新增 `cn/` 目录，纯静态 + 少量原生脚本）

- 页面：首页 `/`、教练目录 `/coaches`、教练主页 `/c/<短名>`、隐私政策 `/privacy`、未开放页。
- 目录与主页的数据由浏览器请求同域的 `/api/public/*` 取得；官网服务器把这条路径反向代理到后端的 `/public/*`，**只代理这一条前缀**。
- 导航的「教练目录」一项与首页的目录入口：`total ≥ 5` 才出现。
- 教练主页自上而下：头像与名字、一句话简介、擅长方向、简介、核实数据三块（各带「MeetPR 核实」标识与「数据截至」）、招生申请表单、页脚。自述区与核实数据区在视觉上必须一眼分得开。
- 招生申请表单下方有一行告知：所填信息只提供给这位教练用于联系你。提交成功后原地显示「已发送」。
- 二维码海报在浏览器里生成（教练头像或首字、名字、一句话简介、二维码、官网标识），不经后端。
- 隐私政策补一条：匿名化的训练数据可用于教练主页的统计展示；并说明招生申请表单收集什么、给谁、保存多久。
- 现有 `meetpr.app` 英文站不受影响；`cn/` 目录不随英文站发布。

## §7 存量数据与老用户

- 迁移纯加法，不回填。现有教练没有主页行、订阅到期日为空 → **不对外可见**，带训工具的使用完全不受影响。
- 现有教练第一次打开「我的主页」时当场得到一份空草稿；其历史带训记录不需要任何搬运，核实数据直接从既有记录算出，预览里立刻能看到。
- 订阅到期日为空或已过期只影响主页的对外可见，**不限制**排计划、看视频、聊天等现有功能。
- 现有学员：不新增任何需要学员操作的步骤；app 不变。学员的记录以匿名形式进入其教练主页的统计。
- 老用户升级后的第一屏：教练登录网页端后的首屏不变，只是导航多出两项；管理员后台首屏不变，多一个分区。
- 现有静态官网首页被新首页取代前，先把线上那张页面的原文件存档进 `meetpr-site`。

## 验收清单

后端（先红后绿）：

1. 新教练 `GET /coach/page` 得到草稿；`GET /public/coaches/:slug` 对草稿、待审核、已隐藏、已下线、订阅为空、订阅已过期六种情形都回同一个 404。
2. 设短名与一句话简介 → 申请公开 → 管理员通过 → 订阅未到期：主页与目录都能读到；入驻时间写入且此后不变。
3. 订阅到期日拨到过去：主页 404、目录不含、招生申请 404；拨回未来即恢复，入驻时间与排序不变。
4. 教练隐藏再恢复不需要再审；管理员下线后教练 `show` 被拒。
5. 已公开状态改自述立即对外生效并出现在管理员「改动待看」里；标记可清除。
6. 短名：格式、保留词、重复、首审后锁定四种拒绝各有测试；管理员可改。
7. 核实数据：给定一组构造的记录，带训规模四个数、每名学员每项的起点／现值／变化／周数、破纪录次数、响应中位数与样本数都与手算一致；含一名进步为负的学员、一名只有辅助项记录的学员、一名只有导入估算的学员（后两者不出现在学员进步里）。
8. 公开响应里不出现任何学员姓名、id、日期；用断言逐字段检查。
9. 招生申请：成功 201 并入库；诱饵字段被填时 201 但不入库；24 小时第 4 条 429；教练只能读到和改到自己的。
10. 邮件提醒：有邮箱且已配发信时发出且正文不含访客内容；无邮箱或未配发信时跳过，接口仍 201。
11. 现有接口的响应与迁移前逐字节一致（抽 `GET /coach/students`、`GET /me`、`GET /admin/overview`）。

网页端：

12. 教练能完成「填自述 → 预览 → 申请公开」，预览里的数字与公开接口一致。
13. 管理员能在后台完成通过、退回（教练能看到理由）、下线、恢复、设置订阅到期日。
14. 招生申请列表、角标与改状态可用。
15. 带历史数据的老教练账号登录后首屏与现在一致，原有功能逐项可用。
