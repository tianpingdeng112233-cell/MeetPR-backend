# 063 — 教练点评（meetpr.cn「教练点评」板块）

- **状态**: Ready（2026-11-09 /grill 三轮，同日 David「确认」）
- **来源**: David 要让力量举爱好者公开点评中国力量举教练。教练名单由 David 另行在飞书多维表格搜集（字段见 §1）。
- **范围**: 后端（`MeetPR-backend` `staging`，国内轨）+ meetpr.cn 前端板块（仓与 049 官网前端一致，拆卡时现场定）+ 管理员后台（`meetpr-plan-web` 管理后台）。两个 app 不动。
- **级别 / 节奏**: T2 / P1。新增数据表（迁移号拆卡时现场取下一个空号）；新增对外的公开读接口与登录写接口。UI 卡等屏幕稿「定稿」再派。
- **相关**: spec 049（官网 + 教练目录 + 教练主页）。本板块**先独立于 049 的教练目录**，暂不合并、不改 049 口径；以后是否并入另起 spec。

## 已拍板

1. 挂在 meetpr.cn 下，板块名「教练点评」，只做国内中文网页；app 不动，海外不做。
2. 先单独做验证，不并入 049 教练目录。
3. 登录用户都能写点评；写的时候**不选**与教练的关系，也**不做**「已验证」标签。
4. 登录 = 手机号 + 短信验证码。
5. 点评人只显示自己起的昵称。
6. 每条点评 = 总分（用户单独打）+ 四个分项：专业度、沟通反馈、训练效果、性价比，均 1–5 星；正文用引导提示让用户自己写。
7. 一个人对同一位教练只能有一条点评，可改可删，改过的标「已修改」。
8. 先发后审：辱骂、留联系方式等在发布时自动拦截；被举报的点评**照常显示**，管理员 3 天内处理。
9. 列表默认按点评数从多到少；点评少于 3 条不显示平均分，显示「点评较少」。
10. 用户可提交名单外的教练，管理员审核后上线。
11. 首版**不做教练认领、不做教练回复**。教练要求整页下架，走页面上公开的管理员联系渠道，人工核实本人后由管理员下架。
12. 教练不能删差评、不能付费买排名。

## 现状（已核实，后端 `origin/staging` 916fd3f）

- 短信发送 `src/services/sms.ts` `sendOtp` 只是占位（写日志、固定返回 `000000`），**从未接过真实短信服务**；国内账号现行登录是邮箱 + 验证码（spec 091）。
- 已有管理员角色与管理接口（`src/routes/admin.ts`、`admin-coach-applications.ts`），有限流中间件 `src/middleware/rateLimit`。
- 名字冲突：`src/routes/reviews.ts` / `handlers/reviews` 已是**训练复盘**（学员训练后的感受 + session RPE）。本功能的代码命名一律用 `coach_reviews` / `listedCoach…`，不得复用或改动现有 `reviews`。

## 变更

### §1 名录教练

- 字段（与飞书名单一致）：必填＝姓名/称呼、网名、性别、抖音号、抖音主页链接、省份、城市、所属场馆/工作室（可多个，可为「无」）、授课方式（线下 / 线上 / 线上+线下）；选填＝最好总成绩(kg)、比赛级别、装备类别（无装备 / 单层装备 / 多层装备）、资质认证、执教年限。
- 状态：`待审核`（用户提交）→ `已上线` ↔ `已下架`；用户提交被拒为 `已拒绝`。
- 唯一性：以抖音号判重（大小写与首尾空白不敏感）。
- 名单导入：管理员上传飞书导出的 Excel / CSV，按表头映射字段；抖音号已存在的行**更新**不新建，结果报告「新建 N / 更新 N / 跳过 N（附原因）」；示例行（姓名含「示例」）跳过。导入的直接 `已上线`。

### §2 公开浏览（不登录可看）

- 列表：每位显示姓名/称呼、网名、省市、授课方式、总分平均（或「点评较少」）、点评数。可按省份、城市、授课方式筛选，按姓名/网名搜索。默认排序：点评数降序，相同时最近一条点评更新的在前，再按名字。
- 教练页：§1 全部字段（抖音号以主页链接形式出现）、总分平均与四个分项平均（均在 ≥3 条时才显示）、点评列表（按发布/修改时间新到旧）。平均分保留 1 位小数。
- `已下架` / `待审核` / `已拒绝` 的教练不在列表出现，直接访问其教练页显示「该教练页面不存在或已下架」。
- 每页底部有「教练本人申请下架 / 投诉」说明与管理员联系渠道（具体渠道由 David 提供，写成配置项，不写死在代码里）。

### §3 账号

- 手机号 + 短信验证码登录；首次写点评前设置昵称（2–16 字，不唯一，不得是手机号）。
- 验证码：6 位、5 分钟有效、同一手机号 60 秒内只能发一次、每日上限与按来源 IP 限流（沿用现有限流中间件）。
- 点评账号与 MeetPR app 账号**互相独立**（同一手机号也不打通）；以后并入 049 时再合并。
- 页面上任何地方都不展示手机号。

### §4 点评

- 一条点评 = 总分 + 四分项（都必填，1–5 整数）+ 正文（必填，10–1000 字）。正文输入框的引导提示示例：「跟了他多久？计划和反馈怎么样？成绩有没有变化？」（终稿文案以屏幕稿为准）。
- 同一账号对同一位教练至多一条；已有则入口变为「修改我的点评」。修改后显示「已修改」；删除后立即从页面消失、平均分重算。
- 发布 / 修改时自动拦截（拒绝提交并说明原因，不入库）：手机号、微信号 / QQ 号样式、网址链接、辱骂词表命中。词表是可由管理员维护的数据，不写死在代码里。
- 只能点评 `已上线` 的教练。

### §5 举报与管理员

- 登录用户可举报任一点评（理由：辱骂人身攻击 / 泄露隐私 / 虚假或广告 / 其他＋说明）；同一账号对同一条只能举报一次。被举报的点评照常显示。
- 管理员后台：
  - 举报队列：显示点评原文、举报理由与次数、距首次举报的时间；超过 3 天未处理的标红。处理＝「保留」（关闭该条全部举报）或「删除点评」。
  - 用户提交的教练队列：通过 → `已上线`；拒绝 → `已拒绝`（可写理由，提交人不另行通知）。
  - 教练管理：搜索、编辑字段、下架 / 恢复上线、名单导入（§1）。
  - 词表维护（§4）。
- 被删除或随教练下架而隐藏的点评**不物理删除**（保留供申诉追溯），只是不展示、不计入平均分。教练恢复上线后其点评恢复展示。

### §6 提交新教练

- 登录用户填 §1 必填字段提交；抖音号已存在时提示「这位教练已经在列表里」并给出链接。提交后进管理员队列，通过前不公开。

## 兼容与上线顺序

- 全部是新增表与新增接口，不改动任何现有表、接口与 app；存量数据无需照护。
- 后端合并即部署 staging；前端板块与管理后台跟随。短信服务商接入与签名申请是对外正式开放的前置条件；正式开放前用 staging 的占位验证码验收。
- 名单首次导入由管理员在后台完成（数据来自 David 的飞书名单，不进仓）。
