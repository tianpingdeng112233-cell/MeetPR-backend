# 026 — 生产数据守护与测试账号安全清理

Status: InProgress

外来教练会把真实学员带入当前环境，数据库因此必须按生产数据对待。测试账号仍需定期清理，但手机号或
UUID 的外观不能单独证明数据可丢弃；任何破坏性操作还必须有可恢复备份，并绑定到运维实际审核过的
账号清单。

## Scope

本变更提供三个配套交付：

1. `scripts/backup-db.ts`：用 `pg_dump` 生成 gzip 全量逻辑备份，先写同目录的进程独占临时文件，
   成功后原子发布，失败不触碰既有备份。
2. `scripts/delete-test-accounts.ts`：默认 dry-run，列出候选账号与直接外键影响；apply 前强制备份，
   并只删除运维通过重复 `--id` 明确确认的候选。
3. `db/migrations/0049-add-users-is-test.sql`：为 `users` 增加
   `is_test boolean NOT NULL DEFAULT false`，并精确回填 0004 已知的两个 seed 账号。

不在范围：自动修改 RDS 策略、自动应用生产迁移、扩大测试手机号或 UUID 白名单、通用用户删除 API、
ORM 或迁移框架。

## `is_test` 设计决策

`is_test` 是人工维护的可丢弃数据标记，不从手机号段或 UUID 形状推断。0049 只按 0004 已知的精确
`(id, phone)` 对回填：

- `00000000-0000-0000-0000-000000000001` / `+8613800000001`
- `00000000-0000-0000-0000-000000000002` / `+8613800000002`

必须同时匹配 ID 与手机号才置位。这避免把恰好落入测试外观范围的真实学员批量标成可删除数据，也让
删除脚本的 `is_test` 与 phone/UUID 正则保持两个独立信号。迁移是 additive、默认 false，可重复应用。
Kysely 手工类型中的 `UsersTable.is_test` 使用 `Generated<boolean>`，插入方可继续省略该列。

`/testacct` 或后续运维创建的测试账号不会由迁移自动识别：造号时应直接写入 `is_test=true`；既有账号
只能在核对身份后按精确 ID 手工标记，例如
`UPDATE public.users SET is_test = true WHERE id = '<reviewed-uuid>';`，禁止用号段批量 UPDATE。

## 删除安全模型

删除必须连续通过以下守卫：

1. 行本身为 `public.users.is_test=true`。
2. 行的 phone 或 UUID 通过脚本内窄白名单正则，作为独立二次信号。
3. 运维先运行默认 dry-run，审核候选、警告与每张直接子表的级联/约束影响。
4. dry-run 输出可复制的 apply 命令，其中逐个包含当次候选的 `--id <uuid>`。
5. `--apply` 要求至少一个 `--id`；传入 ID 若不再是白名单候选则整次事务报错回滚，未传入的候选跳过。
   因而 dry-run 后新增或新标记的账号不会进入已审核命令。
6. apply 在连接删除事务前强制完成全库备份；备份失败则不连接执行删除。
7. 事务内锁定候选行，固定 `public` search path，DELETE 再次检查 `is_test` 与正则，并核对返回行数；
   任一变化都回滚。

## 运维依赖与手动步骤

- **M1 — RDS 自动备份**：生产 RDS 必须启用自动备份与时间点恢复、监控成功率，并至少保留 7 天。
  应用层脚本只是危险操作前的第二恢复路径，不替代 RDS。
- **M2 — 收窄白名单**：每次准备清理前人工复核脚本内 phone/UUID 范围；只能收窄或显式加入已确认的
  测试身份，不能为消除 warning 临时放宽。
- **0049 手工应用**：由运维在目标库手工应用并核对两条精确 seed 回填。其它测试账号按上节用精确 ID
  UPDATE，或在创建时置 `is_test=true`。
- 清理顺序固定为：确认 RDS 恢复点 → dry-run → 审核生成的 ID 命令 → apply 强制本地备份 → 删除。

## 测试策略

- 备份脚本覆盖参数、文件名/数据库名、字节格式、敏感信息脱敏、`pg_dump` 的 ENOENT/非零退出/信号，
  以及失败只清理自身 `.partial`、拒绝覆盖既有目标。
- 删除脚本覆盖白名单正反边界、apply 参数约束、未知参数、显式 ID 与候选交集，以及任何传入的非候选
  ID 导致整次中止。
- 0049 用 pg-mem 的最小 `users` 表验证两个 seed 精确回填、真实学员不变和重复应用幂等。pg-mem
  不支持 PostgreSQL `~` 正则；0049 刻意使用精确 row-value `IN`，因此迁移测试不需要注册或模拟正则。
